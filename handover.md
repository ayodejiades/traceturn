## 1. What this is

**traceturn is deterministic forensics for multi-agent transcripts.** Given JSONL logs of a swarm of agents, it answers three questions with no model in the loop:

1. **Provenance**: who first stated a number, and who repeated it without checking it.
2. **Propagation**: how far it spread, how long until someone corrected it, who kept repeating it afterwards.
3. **Consequence**: what agents *did* with it (submitted, posted, wrote, handed off). An act is admissible only if its claim traces to an observation; otherwise it is an *ungrounded act*, ranked by blast radius.

The moat: the kernel is a pure function of the transcript, so every verdict re-derives byte-identical offline. Each verdict carries a verbatim excerpt bound to its source record and fails closed if the excerpt is missing. Absence of a provenance edge is a **lower bound, never proof of fabrication**, and the UI says so.

It is a submission for the **AI Swarm Dynamics Hackathon** (hosted by AI Village and Grove Research). Track: "Primary Hackathon Track: end-to-end deterministic kernel and `/proof` verification". Live: https://traceturn.vercel.app. Repo: `github.com/ayodejiades/traceturn`. Owner: Ayodeji Adesegun (`ayodejiades`).

It is **not** an LLM log summarizer, LangSmith, an eval harness, or a sentiment dashboard. The test: given an incident with no transcript summary, the output should be *an origin turn, a derivation count, and a list of acts taken on the gap*, not a paragraph.

## 6. The consequence layer (`lib/acts.ts`)

An **act** is an agent putting a shared claim somewhere: submitted, posted, wrote, handed off. Three evidence grades, strongest first:
- `logged`: a tool call / bash command / typed text whose argument writes the number (from `computer_use_turns` or generic tool rows).
- `reported`: the agent's own past-tense sentence ("answered 9.90", "updated the README to 476 events").
- `planned`: a computer-session goal to do it ("Update X to reflect 487 events").

**Grounding** at the moment of the act: `AFTER_CORRECTION` (someone had already corrected the value) > `UNGROUNDED` (no agent had reported checking it) > `GROUNDED`. Observers are agents who reported their own check (an INDEPENDENT statement, an origin sentence that reports a check, a checked statement before a correction, or the actor's own sentence). Unlike the kernel, **the origin is not a derivation path by default**: stating a number first is not observing it.

Key details that took work to get right (do not regress these):
- **`commandWritesAt(command, pos)`** decides whether a number in a shell command sits in text the command *writes*: a real redirect (not `->`, `2>&1`, `<strong>`), `tee`, `sed -i`/`perl -pi` (replacement side only, not the pattern being replaced), `git commit`/`tag`, `gh ... create|comment|edit`, curl POST bodies, multi-line quoted bodies of those, heredocs opened by a writing statement, and scripts that call `.write(`/`open(...,'w')`/`json.dump`. Comments (`# ...`), `echo` to the terminal, `print`, `grep` needles do not count. 9 unit tests in `tests/acts.test.mjs`.
- **`UNIT_RE` in `lib/lineage.ts`**: the unit word must be on the *same line* as the number and not the front of an identifier (`110\n total_coding` is not "110 total"). This once inflated act counts and moved restatements 2,025 to 2,022.
- **Incident ranking** (`rankIncidents` in `lib/report.ts`): (1) a value someone later **corrected** outranks one nobody challenged (a widely repeated uncorrected number may simply be true); (2) most **distinct agents** acting without a reported check; (3) acts after the correction; (4) downstream reach; (5) ungrounded acts. Breadth before repetition: one agent re-saving a value ten times is one decision. Do not rank by raw act count.
- `actLedger` rows are `[id, claim, grounding, evidence, kind, reach, state, agent]`; `claim:verify` re-derives all act totals and the distinct-agents-acting-unchecked total from it. The curated `acts` slice always includes the top incident's acts.
- The headline copy must not call after-correction acts "unobserved" (they may have observers of the wrong value). See `IncidentPanel` in `components/acts-view.tsx`.

## 7. The audits (how numbers earn trust)

Two separate audits, same discipline: seeded stratified sample (sha256 order), a **dev set** used to fix rules, then a **held-out set** drawn after the rules are frozen with a different salt and excluding dev items. Only held-out numbers describe the shipped rules. **All labels are by Claude, the model that wrote the rules, so they are not independent**; both docs say so. `claim:verify` joins samples and labels, rejects unlabelled items or unknown codes, regenerates the docs, and asserts the write-up quotes the figures.

- **Classifier audit** (`docs/AUDIT.md`, `evidence/audit-*.json`, `pnpm audit:sample`): held-out agreement 65/99 (66%): checked 55%, credited 73%, echoed 68%. Estimated true AI Village check rate 15.5% (classifier alone says 6.9%). **Not re-sampled after the `UNIT_RE` change**, which moved some counts (restatements 2,022; credited 403; echoed 1,479).
- **Act audit** (`docs/ACT_AUDIT.md`, `evidence/act-audit-*.json`, `pnpm audit:acts`): 78 dev items, 108 held-out. Codes: `Y` real act, `YC` real act but the window shows a check the grounding missed, `YT` real act but it preceded the correction it was graded after, `Q` not the same quantity, `N` same number not an act, `U` unclear. Held-out: **86/108 real (80%)**; AI Village 46/68 (68%; **82% population-weighted**; logged 84%, reported and planned 47% each but tiny strata); wiki 40/40. Failure modes: the extractor taking names/ids for quantities ("311 data", "374 FALSE", "$170" in a title; 12 items), audience/outcome/replaced-value/game-move numbers (10 items), grounding that missed a reported check (4, so ungrounded counts are an upper bound), and wiki timing (a wiki act is an edit *reporting* an answer; its time is the report's, so after-correction counts there may be overstated; 2 of 10 sampled explicitly preceded the correction).
- **Independent labelling kit:** `pnpm audit:sheet [n]` writes a blind CSV (`evidence/act-audit-labelsheet.csv`, 40 items committed, no labels and no grades); `pnpm audit:compare <filled.csv> [--write name]` scores a second annotator against the first (raw agreement on "real act" and Cohen's kappa); `docs/LABELLING.md` explains the task. **No independent labels exist yet.** The model that wrote the rules must not fill the sheet and call it independent.
- The dev set led to exactly one rule change (the `sed -i` pattern side). Do not fit rules to the held-out items; if you change act rules or the extractor, draw a **new** held-out set (change `SALT` in `tools/audit-acts.ts`) and label it before quoting new precision.

- Port **3100 is another app** ("PayPulse"). `.claude/launch.json` points at it. Run traceturn with `pnpm exec next dev --port 3217`, and kill it when done.
- macOS: `sed -i ''` (empty suffix), and `zcat` wants `.Z`; use `gzip -dc`.
- Do not chain `sleep` in shell commands; use a background command or a real wait.
- `git filter-branch` refuses to run with unstaged changes; stash `next-env.d.ts` first. Keep a backup ref before any rewrite. The last rewrite was authorised explicitly by the user; a new one needs a new go-ahead.
- Editing `tests/sponsors.test.mjs` by slicing from a test name to end-of-file silently deletes later tests. Check `grep -c '^test('` after such edits.
- Changing `extractClaims` or `UNIT_RE` ripples through every lineage, both reports, all quoted doc numbers, and the classifier audit. `claim:verify` catches numbers it asserts (see `expected` in `tools/verify-evidence.ts`), but not every prose mention; grep the docs for old figures (`docs/FINDINGS.md`, `docs/AUDIT.md`, `docs/HARD_THING.md`, `docs/SPONSOR_FINDINGS.md`, `CLAIM_LEDGER.md`, `README.md`).
